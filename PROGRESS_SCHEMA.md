# Формат личного прогресса

Единственный постоянный журнал — `progress.json` в **приватном** репозитории `chess-progress`. Worker не имеет API для произвольных файлов, веток, владельцев или репозиториев: путь и репозиторий задаются серверной конфигурацией.

```json
{ "schemaVersion": 1, "events": [] }
```

Полная схема: [docs/schemas/progress.schema.json](docs/schemas/progress.schema.json). Дополнительные смысловые проверки заданы в `eventSchema` из [src/lib/schema.ts](src/lib/schema.ts): первый ход должен соответствовать первой попытке, время завершения не предшествует началу, самостоятельное решение требует реальных ходов.

## Событие

Одно событие описывает **завершённое упражнение**, а не отдельный ход. Пример сокращён до одного действия; обычный решённый многоходовый вариант содержит всю фактическую последовательность.

```json
{
  "schemaVersion": 1,
  "id": "00c4de25-61a0-4f5b-a284-69b907770f13",
  "sessionId": "bbd40623-8491-45a5-b756-4d699ac6c3c1",
  "contentId": "diag-05-000pa",
  "contentVersion": 1,
  "kind": "puzzle",
  "mode": "diagnostic",
  "category": "Мат в один ход",
  "startedAt": "2026-10-27T10:00:00.000Z",
  "completedAt": "2026-10-27T10:01:00.000Z",
  "durationMs": 60000,
  "attempts": [
    {
      "uci": "f8b8",
      "san": "Rb8#",
      "fen": "5rk1/5pp1/7p/3p4/1KpPn3/4PPP1/1P2N1P1/r4R1R b - - 0 24",
      "correct": true,
      "at": 60000
    }
  ],
  "hints": 0,
  "outcome": "solved",
  "firstMove": "f8b8",
  "playedLine": ["f8b8"]
}
```

| Поле                          | Значение                                                                          |
| ----------------------------- | --------------------------------------------------------------------------------- |
| `id`                          | UUID завершённой попытки; неизменен при сетевом повторе                           |
| `sessionId`                   | UUID занятия; новая диагностика получает новый UUID, продолжение — прежний        |
| `contentId`, `contentVersion` | Стабильный ID и версия изученного материала                                       |
| `kind`                        | `puzzle` или `opening`                                                            |
| `mode`                        | `diagnostic`, `practice`, `opening`                                               |
| `startedAt`, `completedAt`    | UTC ISO 8601; время браузера, не серверный доказательный timestamp                |
| `durationMs`                  | Справочное время, до 7 суток; нет штрафа за медленное решение                     |
| `attempts`                    | Все легальные ходы, предложенные учеником, включая неправильные                   |
| `attempts[].fen`              | Позиция **перед** предложенным ходом                                              |
| `attempts[].correct`          | Совпадение с учебным решением или репертуарной линией                             |
| `attempts[].at`               | Миллисекунды от начала задания                                                    |
| `hints`                       | Использование подсказки; текущий интерфейс выдаёт одну подсказку                  |
| `outcome`                     | `solved` — решено; `revealed` — добровольно открыт разбор                         |
| `firstMove`                   | Первый реальный легальный предложенный ход; `null`, если разбор открыт до попытки |
| `playedLine`                  | Фактически принятые ходы ученика **и автоматические ответы** соперника, UCI       |

Нелегальный ход блокирует chess.js и не записывает как шахматную попытку. Неправильный легальный ход записывается в `attempts`, но позиция возвращается: такой ход не попадает в `playedLine`. При добровольном разборе `playedLine` может быть неполной или пустой; приложение не выдумывает ходы пользователя.

Количество попыток в упражнении — `attempts.length`; число ошибок — количество `correct: false`. «С первой попытки» в статистике означает `outcome: solved`, отсутствие неправильных ходов на всей линии и отсутствие подсказок. Открытие разбора учитывается в истории, но не в успешных самостоятельных решениях.

Для дебютов несовпадение с репертуаром не обязательно является плохим шахматным ходом. Тренеру следует читать это как ошибку воспроизведения выбранной линии. По материалам и результатам не вычисляется искусственный Elo.

## API и подтверждение

- `GET /api/progress` — только с действующей owner-сессией, заново читает GitHub.
- `POST /api/progress` — одно событие JSON, максимум 32 KiB, только с owner-сессией.
- Ответ успеха: `{"id":"…","saved":true,"duplicate":false}`. Ответ с `duplicate:true` подтверждает, что **идентичное** событие уже находится в GitHub.
- `401`: вход/сессия; `403`: чужой Origin или пользователь; `409`: конфликт записи/ID; `429`: повторить позже; `502`: GitHub недоступен; `503`: настройки или репозиторий не приватен; `507`: файл достиг предела обслуживания.

Worker читает текущий SHA, объединяет событие по ID и выполняет GitHub Contents PUT. При `409/422` перечитывает файл и повторяет до четырёх раз. Запоздалый повтор после потерянного сетевого ответа не создаёт дубликат. Повторный ID с иным содержимым отклоняется, старый результат не перезаписывается. Повреждённый файл прогресса не заменяется пустым журналом.

Нет коммитов на перетаскивание фигуры. На каждое новое завершённое упражнение приходится один успешный commit. При обычном сохранении выполняются проверка приватности, чтение файла и запись; страницу прогресса не нужно часто обновлять. Worker ограничен 60 запросами/минуту на IP; дополнительно действуют лимиты GitHub API.

Журнал рассчитан на одного человека. Предельный размер файла — 8 MB. До достижения этого предела владельцу потребуется спланировать версию схемы с архивами/пагинацией; текущее приложение не удаляет и не архивирует события автоматически. Git history дополнительно сохраняет изменения, но не заменяет корректную резервную копию приватного репозитория.

## Ошибки и экспорт

Неподтверждённая очередь находится только в памяти React-контекста и остаётся при навигации между разделами. Есть повторная отправка; после восстановления авторизации очередь автоматически отправляется повторно. Кнопка «Экспорт JSON» выгружает:

```json
{ "schemaVersion": 1, "events": [], "pending": [] }
```

`events` — подтверждённые облаком записи, `pending` — ещё не подтверждённые события. Экспорт не означает сохранения в GitHub. Это добровольная загрузка файла пользователем, а не автоматическая база на телефоне. При ручном восстановлении через GitHub объединяйте обе коллекции по UUID, валидируйте схему и сохраняйте старую историю. В публичный репозиторий такие файлы не добавлять.

При повторном прохождении `contentId` сохраняется, а `id` новый. Группировка диагностик выполняется по `mode: diagnostic` и `sessionId`; неполные сессии видны как `N/15`. Продолжение с главной страницы выбирает следующую ещё не завершённую позицию последней диагностики по облачным записям.

Внешний тренер должен запросить разрешение GitHub-интеграции на приватный репозиторий. Worker не предоставляет публичный read URL для истории и не отправляет результаты в OpenAI API.
