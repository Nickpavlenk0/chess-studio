# Как добавить задачу

Создайте отдельный файл `src/data/puzzles/NN-stable-name.json`. Каталог автоматически обнаруживается Vite; импорты и компоненты менять не нужно. Обычная новая задача появится в тренировках, но не изменит состав начальной диагностики.

Источники истины: [src/lib/schema.ts](src/lib/schema.ts) и [docs/schemas/puzzle.schema.json](docs/schemas/puzzle.schema.json). Используется `schemaVersion: 1`. Для образца возьмите любой существующий файл с уже проверенным решением.

| Поле                   | Смысл                                                                             |
| ---------------------- | --------------------------------------------------------------------------------- |
| `id`                   | Уникальный стабильный ID, строчные латинские буквы, цифры и дефисы, 2–80 символов |
| `version`              | Целое число с 1; увеличивать при изменении позиции, ответа или смысла объяснения  |
| `title`, `instruction` | Название и задание по-русски, без раскрытия хода                                  |
| `fen`, `side`          | Полный FEN и сторона ученика: `w` или `b`                                         |
| `category`             | Один основной диагностический навык                                               |
| `difficulty`           | `Базовая`, `Средняя`, `Выше средней`                                              |
| `solutions`            | Массив допустимых полных линий в UCI                                              |
| `hint`                 | Одна содержательная подсказка, предпочтительно о мотиве, а не точном ходе         |
| `explanation`          | Объяснение реальных угроз, защитников и результата                                |
| `source`               | Источник позиции, ссылка и лицензия                                               |
| `verification`         | Движок, глубина, проверенные лучшие ходы, оценка со стороны ученика               |

Пример линии: `[["e5c7", "a5b4", "c7d8"]]`. Индексы 0, 2, 4 — ходы ученика; 1, 3 — автоматические ответы соперника. Каждая линия должна заканчиваться ходом ученика. Превращение записывается явно: `g7g8q`; SAN генерируется chess.js, а не хранится вместо UCI.

Допустимые альтернативы добавляются отдельными линиями. При общем префиксе и нескольких ответах противника приложение выбирает первую совместимую линию; после выбранного ответа принимает все совместимые продолжения ученика. Не следует добавлять заведомо ошибочный ход как альтернативу только потому, что он легален.

## Проверка перед PR

```sh
npm ci
npm run check
pip install python-chess
python scripts/validate-fens.py
```

Проверка легальности не доказывает тактическую корректность. Для новой задачи дополнительно проверьте решение надёжным движком и глазами. Посчитайте материал до и после, проверьте защитные ответы и прочтите объяснение по доске. Если доказать корректность не удалось, не включайте позицию в публикацию.

Для повторной проверки всех диагностических решений:

```sh
pip install python-chess
STOCKFISH_PATH=/absolute/path/to/stockfish python scripts/audit-engine.py
```

Требуется отдельно установленный Stockfish; бинарник не входит в проект. Скрипт проверяет легальность, все ходы ученика на глубине 20, мат в соответствующих категориях и обновляет `docs/content-verification.json`. Оценки движка не являются Elo ученика и не показываются как его рейтинг.

Начальный набор взят из базы Lichess `https://database.lichess.org/#puzzles` (CC0). FEN в базе стоит **перед** первым ходом списка `Moves`: сначала сделайте этот ход, затем сохраняйте полученную позицию и оставшиеся ходы как решение. Прямое копирование исходного FEN без этого шага даст задачу за неверную сторону.

## Стабильность и ошибки

Не меняйте `id` существующей задачи. Не переиспользуйте удалённый ID для новой позиции. Повторные прохождения должны ссылаться на один ID и разные UUID событий. Версию увеличивайте, сохраняя старые версии в Git history.

CI отклоняет повторяющиеся ID, неверные схемы, FEN и нелегальные решения. Во время работы приложения семантически неверный файл изолируется и показывается сообщение о недоступном материале; остальные работают. Синтаксически повреждённый JSON останавливает сборку, поэтому не попадёт на сайт через успешный CI.

Чтобы изменить именно начальный тест, отредактируйте `src/data/diagnostic.json`: порядок `taskIds` определяет порядок задач. Не включайте один ID дважды; все ID должны существовать. Добавление обычной тренировки этого файла не требует.

Изменения схем: обновите TypeScript, выполните `npm run schemas` и включите JSON Schema в тот же PR. Новая несовместимая структура требует новой версии схемы и явной миграции существующего прогресса.
